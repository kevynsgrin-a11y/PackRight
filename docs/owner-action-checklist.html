4. Verify the airline dataset — the big one

Every record ships status: "unverified" with verified_at: null, so the site shows “Review pending” everywhere. That is deliberate and honest — the figures were carried over from the original build and have never been checked against the airlines. Use the two Gemini deep-research prompts I gave you; the second one ends with a JSON block shaped to drop straight into data/reference-data.json.

Southwest is the priority. It is modelled as two free checked bags, which changed during 2025. Anyone planning a Southwest trip on the current data gets a materially wrong answer.

Also worth capturing: real overweight and oversize fee bands. Four figures in the engine ($100 oversize personal, $100 gate carry-on, $100 overweight, $150 third bag) are inherited placeholders, shown with an “Assumption” badge. Real banded figures let those be deleted entirely.

One thing the research should settle: all eight airlines carry an identical 62-inch checked-bag linear limit. 62 inches is the industry-standard figure, so this may well be right — but eight identical unverified values is the signature of a single assumption copied across the table rather than eight figures read off eight airline pages. Worth confirming per airline rather than in aggregate. (The code no longer invents this number when it is missing, but it cannot tell you whether a present one was ever checked.)

Send the results back to me and I will update the dataset, flip verified records, regenerate the seed and re-run the tests.

6. Add www, or drop the redirect — 5 min

There is no www DNS record at all on the zone. The audit noticed www did not resolve; that is why. The redirect rule I shipped in _redirects can never fire until www exists.

Every other site in your portfolio (bountycharts, glp1-fund, ridereadyguide, benefitdial, gochujang, originespana, kbbqguide) has www as a Pages custom domain. This one is the odd one out.

I have removed the redirect rule, because it could never have worked: Cloudflare Pages _redirects matches on path only, so an absolute URL in the source position is inert, and the trailing ! was Netlify syntax. A rule that looks like policy but does nothing is worse than none. To actually canonicalise www: add a proxied www CNAME to the Pages project, add www.luggageliason.com as a custom domain on it, then create a dashboard Redirect Rule (Rules → Redirect Rules) matching that hostname to the apex, 301, preserving path and query. Or decide www is simply not used and leave it absent.

9. Decide on HSTS preload — 5 min, think first

_headers currently sends max-age=63072000; includeSubDomains; preload. The header is safe. Submitting to hstspreload.org is close to irreversible and forces HTTPS on every subdomain for years. Confirm every subdomain you will ever want is HTTPS-ready, then either submit at hstspreload.org or remove the preload token.

10. Durable rate limiting — 10 min

Update: the in-isolate limiter now rejects a request before it reaches the database, rather than after, and its 429 is no longer cacheable. That closes the wasteful part. It is still per-isolate and still not the authoritative control, so this item stands.

The Worker enforces a per-isolate limit and emits accurate RateLimit-* headers, but Workers isolates do not share memory, so it is best effort rather than an account-wide guarantee. Either enable the commented-out rate-limit binding in api/wrangler.toml, or add a WAF rate-limiting rule on packright-api.kevynsgrin.workers.dev. At current traffic this is not urgent.
